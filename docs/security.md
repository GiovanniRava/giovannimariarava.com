# Security

The site is static: there is no server code, no database, no user input and no session, so the main
risks are (1) the browser being tricked into running or embedding something unexpected,
(2) supply-chain compromise of build tooling, and (3) misconfiguration at the edge.
The controls below address those; each is verifiable.

## Response headers (`public/_headers`)

Applied by Cloudflare to every response served from `dist/`. (Cloudflare's `_headers` does not
apply to responses generated by Worker code — there is none here.)

| Header                             | Value                                                                                                                                                                                                                      | Why                                                                                                          |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `Content-Security-Policy`          | `default-src 'none'; script-src 'none'; style-src 'self'; font-src 'self'; img-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'; upgrade-insecure-requests` | Deny everything, then allow only what the site uses. No `unsafe-inline`/`unsafe-eval`, no hashes, no nonces. |
| `X-Content-Type-Options`           | `nosniff`                                                                                                                                                                                                                  | Browsers must trust declared MIME types.                                                                     |
| `Referrer-Policy`                  | `no-referrer`                                                                                                                                                                                                              | Outbound links reveal nothing about the visitor's origin.                                                    |
| `Permissions-Policy`               | deny-list of unused features (camera, microphone, geolocation, payment, usb, …)                                                                                                                                            | Least privilege even if a page were ever compromised.                                                        |
| `Cross-Origin-Opener-Policy`       | `same-origin`                                                                                                                                                                                                              | Isolates the browsing context group.                                                                         |
| `X-Frame-Options`                  | `DENY`                                                                                                                                                                                                                     | Legacy twin of `frame-ancestors 'none'` (clickjacking).                                                      |
| `Cache-Control` (only `/_astro/*`) | `public, max-age=31536000, immutable`                                                                                                                                                                                      | Fingerprinted assets never change under the same name.                                                       |
| `Strict-Transport-Security`        | **not set yet**                                                                                                                                                                                                            | See below.                                                                                                   |

### Why the CSP can be this strict

- `script-src 'none'`: the site ships **no JavaScript**. The JSON-LD `<script type="application/ld+json">`
  blocks are inert data (not executed), so the policy does not affect them.
- `style-src 'self'` works because `build.inlineStylesheets: 'never'` keeps all CSS in one external
  file, and because fonts are not injected as inline `<style>`.
- **Why `@fontsource` and not Astro's Fonts API.** Astro's Fonts API (stable, and a fine choice
  elsewhere) writes the `@font-face` rules as inline `<style>` blocks in every page. Under a strict
  CSP those need `'unsafe-inline'` or per-build hashes. Astro's `security.csp` option can generate
  the hashes, but it delivers them in a `<meta http-equiv>` tag, which cannot carry
  `frame-ancestors` and would then have to be combined with a second policy in the header whose
  `style-src` could not know the hashes. Importing `@fontsource/*` CSS compiles to a normal
  external stylesheet plus woff2 files on our origin: one simple header policy, no hashes.
- If you later add JavaScript, prefer Astro's `security.csp` (hash-based) over loosening
  `script-src` with `'unsafe-inline'`, and re-evaluate this section.

### HSTS: gradual rollout

HSTS makes browsers refuse plain HTTP for the host for `max-age` seconds. It is sticky, so it is
raised in steps and only after the previous step ran without problems. The header lives in
`public/_headers` (one line in the `/*` block), is applied to production and test alike, covers
only the host that sends it (**no `includeSubDomains`, no `preload`** for now), and is ignored by
browsers over plain HTTP, so the HTTP → HTTPS redirect is unaffected. Change it on `develop`, look at the
test site, then release through the usual pull request.

| Stage | `max-age`  | Meaning   | Set on     | Notes                                                  |
| ----- | ---------- | --------- | ---------- | ------------------------------------------------------ |
| 1     | `300`      | 5 minutes | 2026-11-02 | Released to test and production; verified with `curl`. |
| 2     | `86400`    | 1 day     |            | Wait at least 1 day after stage 1 with no issues.      |
| 3     | `604800`   | 1 week    |            |                                                        |
| 4     | `2592000`  | 1 month   |            |                                                        |
| 5     | `31536000` | 1 year    |            | SSL Labs then grades A+.                               |

Fill in the "Set on" column with the release date of each step. Before each step, check that apex,
`www` and `test` all answer on HTTPS. Roll back by deploying `max-age=0`.

Optional and separate decisions: `includeSubDomains` (only when every subdomain, present and
planned, is HTTPS-only) and `preload` with hstspreload.org (only when certain: removal takes months).
The same setting exists in the Cloudflare dashboard (SSL/TLS → Edge Certificates → HSTS); do not
configure it in both places.

## `/.well-known/security.txt` (RFC 9116)

Fields: `Contact` (mailto), `Expires`, `Preferred-Languages`, `Canonical`. The `Expires` value must be
under one year ahead and must be renewed — `npm run check:security-txt` (run in CI) fails when it is
less than 30 days away or malformed, so a lapse cannot go unnoticed. The
`security@giovannimariarava.com` alias exists as a Cloudflare Email Routing rule (tested 2026-10-29). Optionally
sign the file with PGP and add `Encryption:`.

## Privacy by construction

No cookies, no local/session storage, no third-party requests (fonts included), no forms. The only
data processing is the host's standard request handling (see `/privacy`). If you add Cloudflare Web
Analytics, its beacon is a third-party script: the CSP (`script-src`, `connect-src`) **and** `/privacy`
must be updated — a deliberate friction point.

## Supply chain and CI

- **Exact versions** in `package.json` and a committed `package-lock.json`; CI uses `npm ci`, which
  fails if they disagree. `.nvmrc` pins Node.
- **Dependabot** (weekly, grouped) for npm and GitHub Actions. Review each PR; CI runs on it.
- **GitHub Actions pinned by full commit SHA** (tag in a comment), not by mutable tags. The runner
  image is pinned too (`ubuntu-24.04` in `pipeline.yml`, not `ubuntu-latest`); upgrade it deliberately.
- **Least privilege:** workflow token is `contents: read`; checkout uses `persist-credentials: false`;
  the `verify` job never sees secrets; the Cloudflare API token and account ID exist only in the
  `production` Environment and are used only by the `deploy` job on `main`.
- **Deploy safety switch:** `deploy` runs only when repository variable `DEPLOY_ENABLED == 'true'`
  (production) or `STAGING_DEPLOY_ENABLED == 'true'` (test).
- **Separate environments:** production and test use different Workers, GitHub Environments and
  (optionally) different API tokens. Workflow inputs reach shell steps only through `env:`, never
  interpolated into scripts. The test site is built `noindex` (see `docs/environments.md`).
- `npm` reports that `esbuild` and `workerd` have install scripts not approved by an allow-list.
  They are not needed for `astro build` or `wrangler deploy`; `wrangler dev` was tested and works
  without approving them. Leave them unapproved unless something breaks.
- Recommended repository settings (done on GitHub by the owner): protect `main` (PRs required, the
  `Verify` check required), enable secret scanning, Dependabot alerts, and 2FA/passkeys on both
  GitHub and Cloudflare. Restrict the Cloudflare API token to the single account and the
  "Edit Cloudflare Workers" permission, and set an expiry.

## How to verify (do this after every deploy)

1. https://securityheaders.com → target **A+**. HSTS is raised gradually (see above), so expect a lower grade until the
   final step; this is intentional. Re-scan after the HSTS rollout.
2. https://csp-evaluator.withgoogle.com with the CSP above → no findings.
3. Browser DevTools console on every page type → no errors or CSP violations (tested locally with
   headless Chrome against `wrangler dev` on 2026-10-09, with the IBM Plex fonts: 0 console/CSP/network
   errors on home, indexes, detail pages, privacy and cv).
4. `curl -sI https://giovannimariarava.com/` shows the headers; `curl https://giovannimariarava.com/.well-known/security.txt`.
5. https://www.ssllabs.com/ssltest/ (TLS) and https://observatory.mozilla.org.
